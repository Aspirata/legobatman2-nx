# Полные серии RT960 после обрезанного GPU захвата045

2026-11-17. [Контроль045](switch-pipeline-phase-profile.md#аппаратный-результат-run045)
разделил CPU затраты memexport:96,16% — ожидание, allocation+release —3,50мс/с.
Пул буферов отложен как малоперспективный. Гипотеза стоимости960 ещё открыта:
подробный измеритель обрезал2618 сегментов и записал только467 RT960 операций.

Новый контроль сохраняет рендер044 и CPU счётчики045. Init-only
`lb2_gpu_phase_coarse=true` при `lb2_gpu_phase_profile=true` включает два
крупных типа GPU интервалов вместо границ каждого внутреннего вида работы:

- `rt960_sequence`: начинается перед гостевым draw при фактической ширине
  render area960 и продолжается до следующего известного гостевого draw с
  другой шириной либо конца command buffer.
- `other_gpu`: остальная последовательность, включая начальные служебные
  команды до первого гостевого draw.

Compute uploads, copies и внутренние graphics helpers внутри серии не меняют
её тип, даже если временно используют другую ширину render area. Так десятки
переносов или загрузок текстур не исчерпывают все query slots перед поздним960.
По полным trace180/280 известно5/6 гостевых серий960 и11/13 переключений крупных
типов на кадр; для других кадров число не гарантировано.

Это интервал серии вместе с попавшими внутрь служебными командами, а не чистое
время960 guest draws. Входные transfers до первого960 draw могут остаться
снаружи; helpers перед следующим non960 draw могут попасть внутрь. Назначение
поверхности и точная причинная принадлежность transfers/resolves не выводятся
из этих интервалов. Сохраняется отдельный observed census исходных ролей.

Редкий выбор буферов1/32, максимум64 выбранных,8 pools,128 query slots,
лаг4 завершённых submissions, чтение без WAIT и отсутствие дополнительных
drain сохранены. Detailed mode045 доступен при coarse=false; оба измерителя
выключаются через `lb2_gpu_phase_profile=false` и `lb2_gpu_timestamps=false`.
Ни размеры поверхностей, ни shaders, ни MSAA, ни memexport visibility не меняются.

## Проверка полноты

`selected_operations` считает команды в выбранных буферах,
`recorded_operations` — попавшие в реально записанный интервал. При coarse mode
эти числа сохраняются как для исходного census, так и для двух крупных типов.
Исходные роли имеют samples=0 и sampled_ms=0: их команды покрыты общими
интервалами, отдельного GPU времени исходных ролей этот режим не измеряет.

Для вывода о960 требуется равенство selected/recorded у census `guest_rt960`
(sampled_operations=0 у этой строки ожидается). Для сравнения обеих крупных
групп у каждой требуется selected=recorded=sampled_operations после чтения.
Также требуются zero truncated_segments и buffers_read=selected после задержанного чтения.
Если равенства нет, гипотеза остаётся открытой. Даже полный выбранный буфер —
часть выборки, а не доля времени всех кадров; CPU scopes и GPU spans не суммируются.

Регрессия воспроизводит1000 ранних переключений helpers и поздние1000 guest960
draws, перемежаемые compute uploads и graphics helpers с шириной480. Получается
одна полная960 серия и две другие группы, всего8 timestamp writes с outer span.
Вторая проверка намеренно переполняет бюджет100 чередующимися guest960/non960
draws: actual guest960 selected50, recorded32, потеря видна явно.

Материалы — `work/analysis/rt960-coarse-profile/`, app изменения —
`gpu_timestamps.cpp`/`lb2_gpu_timestamps.h`. Новых изменений SDK для этого режима
нет; используется SDK instrumentation045. Аппаратный046 выполнен; результат ниже.
