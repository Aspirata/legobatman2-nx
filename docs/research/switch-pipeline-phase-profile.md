# Измерение разных частей конвейера после run044

2026-11-17. Сохраняет принятые настройки run044 (+14,76% в начальном пролёте,
пользователь подтвердил прежнее изображение). Новый контроль диагностический:
его FPS нельзя напрямую считать результатом оптимизации из-за накладных расходов
timestamp queries. На момент подготовки аппаратного результата ещё нет.

## Что записывает новый режим

Init-only `lb2_gpu_phase_profile=true` включает отдельный режим существующего
измерителя; `lb2_gpu_timestamps=false` сохраняется. Первый command buffer и затем
псевдослучайно примерно один из32 получают замеры, максимум64 выбранных буфера
за запуск и8 query pools. Псевдослучайный выбор избегает привязки к одному и тому же
месту повторяющейся последовательности.

В выбранном буфере timestamp pair ставится на последовательную группу одного
вида работы, вместо пары на каждый draw. Группы: гостевой рендер при ширине
реального render area960, остальной гостевой рендер, ownership transfers, EDRAM
dump, resolve, texture load, host depth, swap, copy/clear и неизвестные draw/compute.
Известные внутренние pipeline roles и гостевые labels сохраняются отдельно.
`guest_rt960` означает именно ширину960, а не доказанное назначение shadow map
или точный размер960×960. Связь transfers/resolves с конкретной гостевой
поверхностью устанавливается отдельной причинной трассой.

Данные читаются только после уже завершённого submission плюс ещё4 завершённых
submissions, без WAIT и дополнительных drain очереди. Повторный опрос того же
завершённого submission исключён. Лимит128 query slots на буфер прекращает запись
последующих сегментов; `truncated_segments` показывает неполноту. Ресурсы
освобождаются в существующем shutdown после ожидания очереди.

В логе выводятся cumulative `sampled_ms`, число сегментов `samples`, число
команд внутри них `sampled_operations` и общее число наблюдавшихся команд
`observed_operations`. Наблюдавшиеся роли с `samples=0` выводятся явно; это
отсутствие выбранного интервала, а не доказанная нулевая стоимость.
`mean_us` относится к сегменту, а не к одному draw.
Это выборочные GPU интервалы внутри command buffers, не полные кадры и не доли
времени кадра. Их нельзя экстраполировать на весь запуск или складывать с CPU
ожиданиями; вмешательство измерителя тоже может влиять на выполнение. После64
выбранных буферов запись GPU замеров прекращается; observed counters продолжают
расти. `first_selected_submission`, `last_selected_submission`, `buffers_read`
показывают границы фактического захвата и число прочитанных буферов.

Новые CPU категории полного memexport пути сохраняют исходные вызовы, их порядок,
обработку ошибок и синхронизацию. Пул allocation и прежний некорректный fast path
не включаются. `memexport_wait` оплачивает ранее поставленную GPU работу и не
показывает потенциальную экономию целиком. Вложенные CPU категории пересекаются
с общими `memexport`, `submit` и `queue_submit`.

## Проверка и аппаратный запуск

Измеритель проверяется recording-backend тестом реального production code:
группировка тысячи draws, распознавание неизвестных helpers, редкая выборка,
лаг чтения, отсутствие WAIT, лимиты ресурсов, rollover и legacy mode.
Тест отдельно переполняет фазовый буфер100 чередующимися группами: ровно128
query writes и37 явно обрезанных сегментов. Direct-color helper учитывается
как resolve; copy/clear включает buffer/image copies и native clears и не
выдаётся за отдельную стоимость memexport GPU-copy.

CPU harness проверяет отдельные категории, точные длительности и сохранение
результатов/ссылок при оборачивании вызовов. ARM64 build и итоговая проверка
установки фиксируются в `work/analysis/pipeline-phase-profile/`.

Финальная ARM64 сборка и все обязательные регрессии прошли (`build-final.log`),
timestamp harness —2537 проверок. Проверка кода завершена без существенных
блокеров после исправления классификации и отчёта о coverage. Инкрементальный
SDK patch: `port/rexglue-horizon-pipeline-phase-profile.patch`; публичные SDK
headers и кэш гостевых объектов не менялись.

Новая пара установлена на консоль, полностью прочитана обратно и проверена
по SHA256 (`verification.json`, `readback/`). Принятая пара044 сохранена
в `preinstall/` до замены:

Единственное изменение настроек относительно044 — `lb2_gpu_phase_profile=true`.

## Аппаратный результат run045

Установленные NRO/TOML прочитаны после запуска и совпали с указанными SHA256.
Журнал `hardware/legobatman2_045.log` имеет SHA256
`0311dfe8b43e43c6fcbe83482ba1ccc4a8b9008538453f9624e5263d28ba4eb3`.
`analyze.py` проверяет идентичность и создаёт `hardware-result.json`.

Первые шесть устойчивых окон:221 кадр за61,50с,3,5935 FPS. Это диагностический
режим с заметным вмешательством timestamp queries, а не сравнение оптимизаций
с run044. За весь журнал1543 deferred=committed,726 alpha_committed,
replay_attempts=0, replay_failed=0, GPU errors=0.

В тех же61,50с CPU memexport:

| Часть | Суммарное время | Мс на секунду наблюдения |
| --- | ---: | ---: |
| Весь memexport, включительно | 6059,43мс | 98,53 |
| Ожидание очереди | 5826,87мс | 94,75 |
| Создание allocation | 83,72мс | 1,36 |
| Освобождение | 131,24мс | 2,13 |
| Map | 1,49мс | 0,024 |
| Invalidate | 4,83мс | 0,079 |
| Memcpy | 10,61мс | 0,173 |

Ожидание — примерно96,16% общего scope memexport. Allocation+release вместе
дают3,50мс/с: пул буферов по этим данным малоперспективен для основного FPS.
Отложенный readback остаётся отдельной гипотезой; время ожидания не равно
возможной экономии, потому что включает ранее поставленную GPU работу.
Окна снимаются с разных потоков, отдельные счётчики могут расходиться на один
переходящий через границу вызов. Включительные CPU scopes не складываются.

GPU захват:53 буфера прочитаны из53 выбранных, последние selected submission1729,
наблюдалось1742 буфера. Нет skipped buffers, но **2618 phase segments обрезаны**
лимитом128 query slots. В выбранных префиксах:ownership433,441мс,
EDRAM dump71,647мс, гостевой RT9601,174мс. Это **не рейтинг стоимости кадра**:
RT960 записан лишь23 сегментами/467 командами при179690 наблюдавшихся командах,
а ранние ownership группы вытесняли поздние сегменты. Нулевая стоимость swap
также не доказана: samples=0. Whole-buffer spans948,109мс не устраняют эту
неполноту классификации.
