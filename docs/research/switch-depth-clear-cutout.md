# Полная очистка depth/stencil: исключение восстановления старых значений

2026-11-17. Основание — [полная последовательная трасса run042](switch-clear-causal-trace.md).
Это первый контроль, меняющий количество GPU-работы по результату этой трассы.
**Run043: 4,61 против4,18 FPS (+10,5%); пользователь подтвердил прежнее изображение.**
Следующий отдельный контроль — [DepthOnly alpha-register extension](switch-depth-only-alpha-clear.md).

## Что показал run042

NRO/config считаны с консоли и совпали с установленной диагностической парой.
Журнал подтвердил сохранение кадров180 и280: 2237/2831 операций,
16491/23968 событий, 807736/1200036 bytes; оба захвата полные, `dropped=0`.
Файлы: `work/analysis/clear-causal-trace/hardware/`, декодированные данные —
`frame180.json`, `frame280.json`, краткие состояния — `clear-summary-*.json`.

Для clear VS `1E6883FCCDE1F688` maxY уже равен фактической высоте: исходный
scissor8192 не вызывает завышения этих конкретных проходов. Перед clear-кандидатами
записано215 из404 transfer draws в кадре180 и287 из530 в кадре280. Это счётчик
работы, не измеренная доля времени GPU; не все эти переносы доказанно избыточны.

Узкий доказанный случай: PS отсутствует; rectangle list из трёх вершин;
нормализованный depth control `0x8777` всегда проходит Z/stencil, пишет Z и
заменяет stencil целиком. Фактические вершины задают480×480; все samples
покрыты; цвет не пишется. Перед ним восстанавливается старый depth/stencil
в тот же полный прямоугольник. Последующие операции590/1188/1243 кадра180
переносят новое содержимое в alias `002062D0`, поэтому сохранять оба аспекта
и точное покрытие обязательно.

Первый контроль допускает только два clear на каждом из этих кадров (операции
565/1163 и855/996). Они вызывают соответственно27 и18 импортных draw — всего
**45 потенциально устранимых transfer draws на кадр**. Другие480×480 clears имеют
включённый alpha test и в этой пробе консервативно отклоняются. Частичные
400×240 и48×480 очистки, PS draws, stencil-only случаи также сохраняют прежний путь.

## Реализация и защита от пропущенного draw

Init-only `lb2_depth_clear_cutout` по умолчанию false. Проверяются точные27 dwords
VS, исходные состояния raster/scissor/rounding, полный sample mask, отсутствие
PS/memexport/query/predication и цветовых записей. Глобальный half_pixel_offset
учтён; допущены только подтверждённые центры пикселей. На каждой EstimateMaxY
старые координаты сбрасываются. Позиции получаются исключительно при уже
существующем выполнении VS: три полных экспорта, конечные значения W=1/Z=1,
точные эффективные углы(0,0),(480,0),(480,480).

Только host RT key `003062D0`, height_used480, used_rts=depth-only, scale1.
Для каждого исходного диапазона **реальный** SDK `GetRectangles` с cutout480×480
должен вернуть0; любые другие accumulated attachments/transfers запрещают пробу.

Общий ChangeOwnership и исходные списки переносов не меняются. Vulkan cache
откладывает их выполнение, сохраняя списки и источники. Только реальный CmdVkDraw
подтверждает полную перезапись. На любом раннем выходе, async placeholder,
ошибке bindings либо пропуске draw область восстанавливается исходными переносами.
Перед replay проверяется открытие submission; невозможность сообщается как ошибка
и `replay_failed`, не выдаётся за успешное восстановление. Публичные заголовки SDK
оставлены побайтово прежними; проверенный ARM64 guest cache не подменялся.

Рисующий clear остаётся исходным. Native clear, новые шейдеры, замена MSAA,
новое выполнение VS, отложенное чтение stencil и изменения memexport не добавлены.

## Проверки

- Host guard/scope tests: точный код, каждый guarded register bit, queries,
  memexport, частичные/повторные/NaN экспорты, оба центра пикселя, вложенные scopes,
  сброс оценки, ранний выход, реальный commit и ошибка подготовки replay.
- CPU oracle: настоящий GetRangeRectangles/AddRectangle текущего SDK, все259560
  непустых поддиапазонов720 tiles. Полный cutout исключает их целиком, внешняя
  строка и неполный край сохраняются.
- Replay фактических состояний обоих кадров через production predicate допускает
  ровно2 clear и45 transfer draws в каждом.
- Независимая проверка кода одобрила защиту от пропущенного draw и время жизни
  оригинальных списков/ресурсов.

Код приложения: `lb2_depth_clear.h`, `depth_clear.cpp`; SDK patch:
`port/rexglue-horizon-depth-clear-cutout.patch`. Данные эксперимента:
`work/analysis/depth-clear-cutout/`. Тесты: `tools/test-switch-depth-clear.py` и
локальный `replay.py`. Новая конфигурация отличается от run039 только
`lb2_depth_clear_cutout=true`; scissor-control, same-origin и запись бинарных
трасс выключены. Сохраняются GPU log filtering и прежние проверенные настройки.

ARM64 build с обязательными регрессиями завершён успешно:
`work/analysis/depth-clear-cutout/build-verified.log`. Исходные SDK файлы сохранены
в `before-sdk/`; обратная применимость нового патча проверена. Финальная проверка
кода одобрена после добавления безопасного replay и сохранения публичных headers.
