# Расширение полной очистки на DepthOnly с неисполняемым alpha test

2026-11-17. Run043 подтвердил [первый guarded clear control](switch-depth-clear-cutout.md):
4,6139 против4,1756 FPS в первых шести устойчивых окнах (+10,50%), stencil draws/frame
347,38 против391,75,965 подтверждённых clear commits,0 replay/failures/GPU errors.
Пользователь подтвердил: «Изображение как раньше». Результат принят для текущего
пролёта; производительность полноценной игры им не установлена.

Следующий контроль сохраняет run043 и включает один дополнительный init-only
`lb2_depth_clear_depth_only_alpha`, по умолчанию false. **Run044 выполнен и принят
для начального пролёта: 4,7918 FPS, изображение прежнее.**

## Почему оставшийся alpha-регистр здесь не мешает полной очистке

В кадре180 операции1218/1277/1351 имеют те же полные480×480, ALWAYS Z/stencil,
Z write, stencil REPLACE/full mask, exact VS и эффективные координаты. В кадре280
тот же случай есть в918/1073/1240/1863. Исходный RB_MODECONTROL=5 (DepthOnly),
эффективный PS отсутствует. Единственная отклонённая прежним guard особенность —
остаточный alpha-test bit с RB_COLORCONTROL8700000E либо8700000C.

В текущем renderer IssueDraw использует PS только для ColorDepth. В создании
Vulkan pipeline при PS=null на hostRT/D24Unorm нет fragment stage вообще.
Ветка float-depth conversion не подходит к pinned key003062D0, FSI исключён
проверкой пути. Поэтому данный alpha test не исполняется и не может отбросить
samples. Гостевая семантика alpha test, MSAA и работа shader не меняются.

Новая оговорка допускает **только** opt-in + raw mode5 + одно из двух указанных
значений colorcontrol. По-прежнему запрещены PS, alpha-to-coverage, queries,
memexport и прочие отличия исходного строгого guard. Результат импорта заменяется
тем же исходным полным draw, после которого старые данные обоих аспектов не нужны.

Дополнительно закрыт редкий случай: cached placeholder не должен подтверждать
очистку даже после выключения reloadable async_shader_compilation. Commit теперь
явно требует !pipeline_is_placeholder; иначе исходные переносы восстанавливаются.
В run043 этого случая не было (replay counters0), его FPS результат не пересчитан.

## Проверки

Новые unit tests проверяют обе наблюдавшиеся alpha-функции и запрет PS, других
EDRAM modes, alpha-to-coverage и неизвестных регистров. Cached placeholder вызывает
replay. Старые program/state/coverage/fallback проверки и259560 SDK partitions
сохранены.

Повтор фактических trace states через production code:

| Режим | Кадр180 | Кадр280 |
| --- | --- | --- |
| Флаг OFF, прежний043 | 2 clear /45 draws | 2 clear /45 draws |
| Флаг ON | 5 clear /72 draws | 6 clear /81 draws |

Эти числа описывают устранимую работу в двух захватах, не дополнительный прирост FPS.
Материалы: `work/analysis/depth-only-alpha-clear/`, app code — существующие
`lb2_depth_clear.h`/`depth_clear.cpp`, SDK patch —
`port/rexglue-horizon-depth-only-alpha-clear.patch`, поверх предыдущего cutout patch.
Публичные SDK headers не изменены. Диагностическая запись файлов и GPU timestamps
остаются выключенными; memexport и остальные настройки043 сохраняются.

ARM64 build и обязательные регрессии прошли (`build.log`). Код повторно проверен
после добавления второй наблюдавшейся alpha-функции и non-placeholder commit;
существенных замечаний нет. Инкрементальный SDK patch обратно применим к текущим
исходникам.
