# LEGO Batman 2 Recomp — Nintendo Switch

Экспериментальный перенос **LEGO Batman 2: DC Super Heroes** с Xbox 360 на Windows и Nintendo Switch с помощью статической рекомпиляции PowerPC и среды исполнения ReXGlue. Проект находится в разработке и пока не готов к полноценному прохождению на Switch.

Это мой первый проект такого рода, и у меня пока нет опыта в подобной разработке. Я публикую репозиторий **как есть**: здесь есть работающий код, незавершённые эксперименты и исследовательские заметки. Я продолжаю разбираться с проблемами и буду постепенно улучшать проект в свободное время; сроков исправлений и готового результата пока нет. Портирование выполняется с помощью ChatGPT.

## Состояние

На Windows игру можно пройти; сохраняются периодические подлагивания. На Switch запускаются меню, звук и управление; удалось загрузить сохранение и попасть в игру. Полное прохождение на Switch ещё не подтверждено.

**На Switch игра работает примерно с 3 FPS и при 720p, и при внутреннем разрешении 848×480.** Текущее узкое место связано с программным графическим стеком: переводом команд Xenos, Mesa NVK и работой очереди рендера. Профилирование выявило большое ожидание в `vkQueueSubmit` и нагрузку от переносов графических ресурсов. Само место ожидания не доказывает, какая именно часть драйвера, синхронизации или GPU-работы первопричина; предел вычислительной мощности консоли этим замером не установлен. Готового исправления пока нет. В главном меню также есть ошибка отрисовки, похожая на ошибку глубины; пока её исследование отложено.

[Техническая документация и история разработки](docs/porting-casebook.md)

В одном эксперименте начальный пролёт показал **4,79 FPS против 4,18 FPS**; это результат конкретной сцены, а не показатель всей игры. Последующие эксперименты и их ограничения описаны в [исследовательских заметках](docs/research/switch-depth-only-alpha-clear.md). Некоторые изменения ещё ждут проверки на консоли, в том числе [проба 048](docs/research/switch-stencil-zero-reuse.md).

### Известные проблемы и дальнейшая работа

- **Switch:** производительность пока очень низкая, причина основного замедления окончательно не установлена. Я изучаю графический тракт и проверяю оптимизации на корректность и скорость.
- **Изображение на Switch:** в главном меню наблюдаются артефакты, напоминающие проблему глубины. В одном из экспериментов также сообщалось о возможных новых артефактах; их связь с изменением не доказана и требует отдельной проверки.
- **Стабильность и совместимость:** полное прохождение, переходы, звук и сохранения на Switch ещё не проверены во всех сценариях. На Windows остаются периодические подлагивания.
- **Сборка:** настройка зависит от локальных инструментов и закреплённых версий; сборка с нуля на другой машине ещё не проверена.
- **Распространение:** условия отдельных зависимостей и распространения готовых сборок требуют дополнительной проверки.

План — постепенно исследовать производительность и артефакты, расширять проверки на реальном устройстве и упрощать сборку. Возможности и сроки зависят от результатов исследования.

Тестовый ПК: AMD Ryzen 7 5700X, NVIDIA GeForce RTX 5060 Ti (8 ГБ), 16 ГБ оперативной памяти. Тестовая консоль — Nintendo Switch OLED в портативном режиме: CPU 2397 МГц, GPU 1305 МГц и RAM 2500 МГц. Эти частоты установлены с начала тестирования игры; Governor отключён, поэтому частоты остаются постоянными.

## Что потребуется

- Собственная копия поддерживаемого издания игры для Xbox 360. Игровые файлы, ISO, XEX и сгенерированный код в репозиторий не входят. Поддерживаемая сборка и её хеш указаны в [config/game-build.json](config/game-build.json).
- Для подготовки и сборки: Windows, Python 3.11+, Git и локальные инструменты и зависимости, перечисленные в [руководстве](docs/porting-casebook.md#section-research-switch-game-build-md). Скрипты используют локальный каталог `work/`; готовность чистой установки на другой машине ещё нужно проверить.
- Для запуска на Switch: консоль с возможностью запуска homebrew, SD-карта и hbmenu в режиме приложения. Обычный режим через Альбом не предоставляет необходимый объём памяти.

## Проверка проекта и подготовка игры

В PowerShell из корня репозитория:

```powershell
python tools/project.py doctor
python -m unittest discover -s tests -v
python tools/prepare-game.py "<путь к собственному ISO>"
```

Для анализа уже извлечённого XEX: `python tools/project.py inspect-xex "<путь к default.xex>"`. Эта команда только читает заголовок и не подтверждает совместимость всей игры.

## Сборка и запуск

После подготовки игры и локальных зависимостей Windows-сборка выполняется так:

```powershell
python -m pip install --target work/toolchain/python cmake==3.31.6 ninja==1.11.1.4 capstone==5.0.6
python tools/bootstrap-host.py
./tools/build-host.ps1 -Jobs 4
```

Результат — `build/pc-play/legobatman2.exe`; для обычного запуска используется `launch-game.bat`. Bootstrap рассчитан на закреплённые пакеты и локальный Clang 20.1.3 из Windhawk; другой путь можно передать через `--compiler-root`.

Для Switch подготовьте закреплённые пакеты и Horizon SDK согласно [руководству](docs/porting-casebook.md#section-research-switch-game-build-md), затем:

```powershell
python tools/setup-switch.py
./tools/build-switch-game.ps1
```

Скопируйте содержимое `build/switch-game/sdcard` в корень SD-карты и запустите `switch/legobatman2/legobatman2.nro` из hbmenu в режиме приложения. Пакет содержит ваши локальные игровые данные и не предназначен для распространения. Сохранения и журналы находятся в `switch/legobatman2/userdata` и `switch/legobatman2/logs` соответственно.

## Устройство проекта

- `src/` — запуск и платформенный код Windows и Switch; `switch/` — сборка Horizon.
- `port/` — границы функций, настройки рекомпиляции и патчи зависимостей.
- `tools/` — подготовка данных, сборка и диагностические инструменты; `tests/` — проверки.
- `docs/` — история, доказательства и результаты проверок; `config/` — настройки и закреплённые пакеты.
- `work/`, `build/`, `generated/`, `game/` и `third_party/` — локальные данные, исключённые из Git.
